# Interconnect 雙端通訊協定規格（Windows / Android 共用）

本文件定義 Windows 端（C# / WinForms）與 Android 端（Kotlin）之間的區域網路自動探索與多媒體同步控制協定。

## 1. 埠號配置

| 用途 | 協定 | 埠號 |
|---|---|---|
| LAN 自動發現（UDP 廣播 Beacon） | UDP | 47811 |
| TCP 控制通道（多媒體同步與控制埠） | TCP | 47810 |
| mDNS 服務（Android NsdManager 登記/解析） | UDP | `_interconnect._tcp.` |

## 2. UDP 發現 Beacon（每 1.5 秒廣播一次）

同時向 `255.255.255.255:47811` 與各作用中網卡的子網定向廣播位址發送 UTF-8 字串：

```
INTR-ADV v1|<deviceName>|<platform:WIN|AND>|<controlPort>|0
```

收到 Beacon 後即自動加入區域網路裝置列表（依名稱更新 IP 與埠號）；超過 6 秒未收到則判定為離線。

## 3. TCP 控制通道訊息（Newline-Delimited JSON, UTF-8）

點擊裝置卡片即主動建立 TCP 連線並發送 `hello`，其後每 1.5 秒發送 `ping` 並由對端回覆 `pong` 量測即時往返延遲（`RTT = now - ping.ts`）。

| `t` (訊息型別) | 方向 | 欄位 | 說明 |
|---|---|---|---|
| `hello` | 雙向 | `name`, `platform` | 連線握手與身分交換 |
| `ping` / `pong` | 雙向 | `ts` (Unix ms) | 即時網路延遲 (Ping RTT) 量測與連線心跳維持 |
| `media` | 雙向 | `title`, `artist`, `playing`, `hasControls`, `positionMs`, `durationMs`, `art?` (Base64 JPEG) | 多媒體播放狀態快照（狀態變更時即時推送，封面僅於曲目變更時傳送以節省頻寬） |
| `mediaCmd` | 雙向 | `cmd`: `"play"` \| `"pause"` \| `"next"` \| `"prev"` \| `"seek"` \| `"toggle"`, `positionMs?` | 遠端多媒體播放控制與時間軸跳轉指令 |
| `bye` | 雙向 | - | 主動正常斷線 |

## 4. 雙向多媒體控制整合機制

- **Windows 端 (`WindowsMediaWatcher` + `MediaBridge`)**：
  - 使用 `GlobalSystemMediaTransportControlsSessionManager` (GSMTC) 讀取電腦正在播放的音樂（Spotify、YouTube、Media Player 等），自動擷取標題、演出者、192x192 JPEG 封面與進度並同步至本機 GDI+ 面板與 Android 通知欄；若未開啟外部播放器則自動啟用內建 GDI+ 展示曲目。
  - 使用 `ISystemMediaTransportControlsInterop` (SMTC) 將 Android 傳來的播放資訊註冊至 Windows 系統媒體控制項。
- **Android 端 (`StreamService` + `AndroidMediaWatcher`)**：
  - 使用 `MediaSession` + `Notification.MediaStyle` 在手機通知欄與鎖定畫面顯示電腦端曲目、封面與控制鈕，並於主畫面提供即時控制卡片。
  - 授權「通知存取」後，透過 `MediaSessionManager.getActiveSessions` 讀取手機端播放器狀態並回傳至電腦端顯示與控制。
